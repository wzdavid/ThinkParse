# 产品概述

ThinkParse 是开源的**企业级文档解析系统**。

它通过统一的生产级 HTTP API，把 PDF、扫描件等复杂文档转为 Markdown 与结构化结果，并围绕**大批量、多 GPU、分布式**场景提供可恢复的任务编排与运维能力。解析质量来自成熟引擎（默认 [MinerU](https://github.com/opendatalab/MinerU) 4.0，可选 [Docling](https://github.com/docling-project/docling)）；ThinkParse 负责让解析在真实业务负载下**持续、稳定、可控地运行**。

## 竞争力（宣传点）

1. **大批量文档的稳定可靠解析**  
   异步提交与轮询，任务与产物持久化；引擎或协调器重启后可继续，而不是任务消失或客户端假死。

2. **多 GPU 并行处理**  
   单机由 MinerU Router 按可见卡每卡一个解析进程；ThinkParse 用槽位与在途字节控制并发，避免盲目堆进程打爆内存。多台引擎时通过多个上游地址按负载与档位分摊。

3. **分布式部署**  
   API / 协调器与 GPU 引擎可分机；共享 PostgreSQL 与 S3 兼容对象存储；多台引擎地址统一接入同一套 API。

4. **生产级服务能力**  
   取消、重试、超时、容量闸门、分层健康检查、批次统计与分段耗时——业务系统只对接 ThinkParse，不必各自维护解析进程与队列。

## 要解决的问题

从「引擎本地跑通」到「长期大批量上线」，常见缺口是：

| 现象 | ThinkParse 的做法 |
|---|---|
| 同步接口超时，批量无法排队 | 异步任务 API；`/api/v2` 支持批次 |
| 多卡却只用到一张 | 引擎每卡一进程；ThinkParse 控槽位，并可向多上游分摊 |
| 进程卡死占着 GPU | 隔离引擎、可取消、可重投 |
| API 与模型绑死，难扩容 | 网关无 CUDA；算力节点独立扩 |
| 多机结果对不上 | 对象存储为真相；任务库持久化 |
| 服务「活着」但解析已挂 | `live` / `ready` / `deep` + `/api/v2/stats` |

偶发几份 PDF，直接跑引擎即可。做成 RAG、知识库、智能问答或科研文献流水线时，需要的是 ThinkParse 这一层服务。

## 适合谁

- RAG / 知识库：入库前统一 Markdown 与结构
- 科研与数据处理：批量论文、研报、合同、档案
- AI 应用：文档解析微服务，业务容器不装模型
- 中台：多 GPU / 多节点解析农场

## 目标

1. 提供稳定、可扩展的文档解析**服务**，而不是单机脚本。
2. 支持 CPU、单 GPU、多 GPU 与多机分布式部署。
3. 任务、原文、产物持久化；对外任务 ID 在引擎重启后仍有效。
4. `/api/v1`（异步任务）与 `/api/v2`（上传 / 任务 / 文件 / 批次）两套公开接口。
5. 引擎可插拔：首发 MinerU；Docling 用于选定的非 PDF 格式。

## 非目标

- 不在 ThinkParse 进程内重写版面、OCR、公式、表格或 VLM。
- 不把整页 VLM（`advanced`）设为兼容接口默认档。
- 不承诺对同一篇 PDF 同时跑两个引擎并在线打分。
- 不把引擎模型权重装进网关镜像。

## 与解析引擎的关系

| 组件 | 职责 |
|---|---|
| **ThinkParse** | 企业级服务层：API、任务生命周期、持久化、容量、观测 |
| **MinerU 4.0** | PDF / 图片等解析执行；档位 `flash` / `basic` / `standard` / `advanced` |
| **Docling Serve（可选）** | `.xml`（如 JATS）、`.tex`、`.eml` 等 |

ThinkParse **不是**「某引擎的附属包装」，而是独立的开源企业级文档解析产品；MinerU 是当前默认的高质量执行引擎之一。
